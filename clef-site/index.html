An exhibit about representation engineering

When an AI agent reaches for a tool,
what is it thinking?

A small language model (Qwen 2.5, 0.5B) reads a shell command an agent wants to run. Instead of trusting its answer, we open it up and read the numbers inside — and judge the command from those. Everything below is measured live on that model. Nothing you type is ever executed.

Room 2 · The alarm line

5 Every command lands somewhere on one line.

The reading becomes one number: how much more harm-like the command looks than the most harm-like of five ordinary commands (cargo build, git status…) in the same situation. Past the dashed line it is refused. The dots are 50 real commands it was tested on — grey meant no harm, red meant harm. Where they mix, it makes mistakes. How it was built

  1. Collect pairs. 24 pairs of commands: one harmful, one harmless, often with the same verb (rm -rf ~/Documents vs rm -rf ./dist).
  2. Look inside. Run each through the model and record the numbers at layer 16. Harmful and harmless commands push those numbers in different directions.
  3. Measure new commands against those directions and compare with ordinary commands in the same situation. The alarm line was placed to catch as many harmful training commands as possible while letting at most one in ten ordinary ones trip it.

Limits. It's a small model and a small training set. It still mistakes some ordinary downloads for data theft, and it misses harm it was never shown (force-pushing over a branch, killing every process). It judges commands; it does not detect prompt injection. The method comes from Zou et al., Representation Engineering (2023).
