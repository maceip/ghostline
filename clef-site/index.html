why string filters fail on AI agents — and how reading Layer 16 catches prompt injection

When an AI coding agent reads a repo file, GitHub issue, or web page, hidden instructions inside that text (a prompt injection) can trick the model into running a malicious shell command. Looking at the command string alone won’t save you—and a second “LLM judge” gets tricked by the exact same text.

Instead of reading the model’s words, we read the model’s brain. A language model processes tokens through 24 internal layers of neurons (its residual stream). At Layer 16 of 24 (68% depth), we read the model’s 896-dimensional activation vector before the tool runs. You can use that signal to filter and block bad calls—and right now this live deployment runs in read-only trace mode so you can watch live brain traces stream out of the model.

02 — HOW IT WORKS (IN PLAIN ENGLISH)

      
No black-box guessing. Three steps inside the model’s brain.

      

        You don’t need 7,000 charts to understand what Representation Engineering does.
        Before an AI model executes a tool call, its internal neurons already encode whether
        the action is routine developer work or a hijacked attack:
      

    


    

      

        

          
          STEP 01 · TOOL CALL PROPOSED
        

        
1 Pass

        
0 generation tokens wasted

        
The agent prepares a command

        

          Your agent reads untrusted context — a file, an issue comment, or a web page —
          and proposes a tool call like bash({"cmd": "…"}). From the text alone,
          you cannot tell if you wanted that command or if a prompt injection planted it.
        

      


      

        

          
          STEP 02 · LAYER-16 BRAIN READ
        

        
68%

        
layer 16 of 24 · 896 dimensions

        
We read the residual stream at Layer 16

          896-dimensional activation vector. We compare its angle (harm_cosine) against
          calibrated harm directions (destruction, secret theft, exfiltration)
          and subtract 5 harmless baseline calls on the exact same prompt.

04 — THE RESEARCH FOUNDATION

      
Built on peer-reviewed science. Four papers that make this work.

      

        Reading a transformer’s residual stream to catch prompt injections and harmful tool calls
        is grounded in four papers across Representation Engineering, Circuit Breakers,
        Activation Deltas, and Linear Tool-Call Readout:
      

    


    

      

        

          01 · FOUNDATIONAL RepE · READING, CONTROL, LAT & LoRRA
          arXiv:2310.01405 ↗
        

        
Representation Engineering: A Top-Down Approach to AI Transparency

        
Andy Zou et al. · Center for AI Safety (CAIS), Carnegie Mellon University (2023)

        

          “RepE places population-level representations, rather than neurons or circuits, at the
          center of analysis, equipping us with novel methods for monitoring
          and manipulating high-level cognitive phenomena in deep neural networks.”
        

        

          How we use it: Defines Representation Reading via
          Linear Artificial Tomography (LAT) — extracting directions in activation
          space that correspond to high-level concepts like harm vs. benign execution.
        

      


      

        

          02 · RepE CIRCUIT BREAKERS · SHORT-CIRCUITING HARMFUL CALLS
          arXiv:2406.04313 ↗
        

        
Improving Alignment and Robustness with Circuit Breakers

        
Andy Zou, Long Phan, Justin Wang, et al. · Gray Swan AI / CMU / CAIS (2024)

        

          “By directly targeting the internal representations that give rise to harmful outputs,
          circuit breakers prevent the model from generating harmful content
          even under unseen adversarial attacks and agent tool-use hijacks.”
        

        

          How we use it: Shows that monitoring internal representations mid-network
          catches harmful agent function calls even when surface prompts are obfuscated or injected.
        

      


      

        

          03 · ACTIVATION DELTAS & PROMPT INJECTION · TASKTRACKER
          arXiv:2406.00799 ↗
        

        
Get My Drift? Catching LLM Task Drift with Activation Deltas

        
Sahar Abdelnabi et al. · Microsoft / CISPA (2024)

        

          “Probing the residual activation delta ΔAct = Actx − Actxpri
          isolates indirect prompt injection as measurable task drift.”
        

        

          How we use it: Inspires our per-prompt baseline subtraction — comparing the
          proposed tool call’s Layer-16 activation against a 5-call benign reference panel on the exact same user prompt.
        

      


      

        

          04 · PRE-GENERATION TOOL SUBSPACE · <tool_call> READOUT
          arXiv:2605.07990 ↗
        

        
Tool Calling is Linearly Readable and Steerable in Language Models

        
Zekun Wu, Ze Wang, Seonglae Cho, et al. · UCL / Holistic AI / Imperial College London (2026)

        

          “Across 12 instruction-tuned models up to 27B, tool selection and propensity condense into a
          low-dimensional linear subspace at the final prompt token preceding
          <tool_call>.”
        

        

          How we use it: Confirms across instruction-tuned models (including Qwen) that
          tool-call intent is linearly readable in a single forward pass before generation.
